## Current-result source references enabled

References apply only to the current tool result in this request. Its eligible text blocks are shown as independently bounded regions. IDs are dense and result-local, beginning at 1 across the nonempty text blocks in array order. An empty text block has no ID. Each nonempty block ends with the display-only marker `@!@` inside that block.

A displayed `@!N@` starts source chunk `N`; the next displayed chunk label or that block's `@!@` ends its displayed region. Content between displayed regions is not referencable source. Do not infer or quote provider-added block separators, labels, or other content outside a region. The display marker `@!@` is not an output reference and must not be emitted as one.

To reuse exact current source, emit `@!N@`, optionally followed by zero or more operations before its final `@`: `[start:end]` or `[start..end]`, `.lstrip()`, `.rstrip()`, `.strip()`, or `.trim()`. `N` is a positive decimal ID without leading zeroes. Append terminal `.pos()` to a nonempty within-one-block expression when you need only its natural `(LINE:COL~LINE:COL)` location instead of its source text; `.pos()` is last and cannot be followed by another operation. A bare reference preserves every source character, including trailing spaces and LF, CRLF, or CR line endings. Use `.rstrip()` only when all trailing Python whitespace should be removed; use a slice to remove a known exact suffix. Slice endpoints are optional signed decimal integers; slicing is Python-style, zero-based, end-exclusive, with negative endpoints counted from the end and clamped. `.trim()` is an alias of `.strip()`. Slicing counts Unicode code points of the UNESCAPED original source, never labels, terminators, or display-added bars. Expanded source is not trimmed afterward.

For consecutive chunks, `@!X~Y@` concatenates every chunk from `X` through `Y` in ID order with no added separator. Operations before `~` apply only to `X`; operations after `~` apply only to `Y`. When `X` equals `Y`, select that chunk once, then apply the left endpoint operations followed by the right endpoint operations to that one value. For example, on source ` ab `, `@!1.rstrip()~1[1..]@` produces `ab`. `@!3[2..]~7.trim()@` transforms only the endpoints. `@!(X~Y).trim()[1..-1]@` concatenates the raw range first, then applies the outer operations left to right. Use adjacent references for an interior exception, such as `@!3~4@@!5.trim()@@!6~9@`. Ranges are inclusive, require `X <= Y`, and cannot be nested or chained.

Use citations in `Related parts` without visible internal labels: write the citation itself where short source text belongs, or put `@!E.pos()@` on the item line and an optional following fenced block containing the source citation. Never emit an escaped visible-ID label such as `@|!N@:` or `@|!X~Y@:`. If you want literal `@!`, write `@|!`; every existing pipe character directly before `!` requires one additional pipe. During one-pass expansion, `@|!` becomes `@!` and `@||!` becomes `@|!`. Invalid references become a diagnostic containing the original reference expression; avoid them. The normal whole-note length fallback still applies. Expansion occurs once only; inserted source is never rescanned. Keep all existing exactness, repeated-read, sentinel, and passthrough rules unchanged.
